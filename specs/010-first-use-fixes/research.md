# Research: Правки после первого использования

## R1. Почему оценка карточки долгая (пункт 8)

- **Замер** (2026-10-02, копия хранилища, 489 слов): каждый запрос `/practice/...` ≈ 0,9 с;
  оценка — `POST /rate` + перенаправление на `GET /practice/{id}` ≈ 1,8 с. `cProfile`:
  0,77 с из 0,89 — `time.sleep` внутри `fsrs.Card.__init__` (библиотека ждёт ~1,5 мс, чтобы
  `card_id` по времени был уникальным), вызванный из `CardStore.sync` → `_insert` для каждого
  слова. `insert or ignore` отбрасывал уже существующие карточки, но объект создавался всегда.
  Остальное: отпечаток дерева хранилища ≈ 45 мс.
- **Decision**: `sync` сначала читает множество имеющихся `(entry_id, direction)` одним
  запросом и создаёт объекты FSRS только для недостающих.
- **Rationale**: время запроса перестаёт зависеть от размера словаря; поведение то же.
- **После исправления** (тот же замер, 2026-10-02): `POST /rate` ≈ 80–120 мс, следующая
  карточка ≈ 110–130 мс — оценка целиком ≈ 0,2 с вместо 1,8 с. Разовая цена: при первом
  запуске новой версии заводятся ~490 карточек ru_fr (≈ 0,8 с один раз).
- **Alternatives**: вызывать `sync` только при изменении контента (по отпечатку) — сложнее,
  выигрыш после основного исправления мал; создавать `Card` с явным `card_id` — зависит
  от внутренностей библиотеки.

## R2. Отказ от поэтапного режима

- **Decision**: `sync` всегда заводит обе карточки; ветка «staged» в `rate` и настройка
  `directions` в «Настройках» убираются. Существующие слова получают карточку «русский →
  французский» при первом `sync` новой версии (как новые: срок — сейчас).
- **Rationale**: решение пользователя 2026-10-02. У настоящего хранилища появится ~470 новых
  карточек ru_fr «на сегодня» — это ожидаемо; их ограничивает «слов за подход».
- **Alternatives**: оставить настройку со значением по умолчанию «обе» — пользователь просила
  убрать.

## R3. Перемешивание очереди (пункт 5)

- **Decision**: в `SessionStore.queue` для режимов урок / тема / все / сложные — `random.shuffle`
  всей очереди; для «сегодня» — две группы (уже повторявшиеся с подошедшим сроком, затем новые),
  каждая перемешана. Генератор передаётся в `SessionStore` (в тестах — `random.Random(seed)`).
  Очередь сохраняется в сеансе как сейчас, поэтому отмена и продолжение порции не меняются.
- **Rationale**: прежняя сортировка `(reviewed, due)` у новых карточек с одинаковым сроком
  давала порядок по `entry_id` — всегда те же первые слова.
- **Alternatives**: перемешивать с учётом срока (взвешенно) — избыточно.

## R4. Настройка повторения и размер подхода (пункты 3, 6)

- **Decision**:
  - `GET /practice/setup` принимает `mode`, `lesson`, `topic` и выставляет их в форме;
    `GET /lessons/{n}/practice` перенаправляет на `/practice/setup?mode=lesson&lesson=n`.
  - В форме поле «Слов за подход» (число или пусто = все). При выборе урока / темы Alpine
    очищает поле (все), для других режимов подставляет последнее значение `portion_size`.
  - `POST /practice/start` принимает `portion`; пусто → все; число 1–500 → сохраняется
    в `portion_size` и в `SessionParams`. `SessionStore.start` берёт размер из параметров
    (`source="lesson"` больше не нужен для «все одним подходом»).
  - Поле «Карточек за один подход» удаляется из «Настроек».
  - `GET /practice/count?mode&lesson&topic&kind&direction` → фрагмент «В сеансе: N карточек»
    (HTMX по `change` формы); 0 → «Нет слов для повторения», кнопка «Начать» неактивна.
- **Rationale**: одно место для всех настроек (ответ пользователя на пункт 3).

## R5. Поле выбора темы с поиском (пункт 11)

- **Decision**: частичный шаблон `partials/combobox.html` на Alpine.js: видимое поле ввода,
  скрытое `<input name="topic">`, выпадающий список `role="listbox"`. По фокусу / клику —
  весь список; по вводу — фильтр «подстрока без регистра и акцентов» (`normalize("NFD")`
  и удаление диакритики), стрелки / Enter / Escape, «Ничего не найдено». Список тем —
  JSON в атрибуте. Без выбранной темы в режиме «по теме» «Начать» неактивна.
- **Alternatives**: `<datalist>` — не фильтрует без акцентов и выглядит по-разному в браузерах;
  поиск через сервер — лишний для десятков тем.

## R6. Род на карточке «русский → французский» (пункт 2)

- **Decision**: класс `gender-*` остаётся на карточке для обратной стороны; лицевая сторона
  при `direction == "ru_fr"` получает класс `neutral` — полоска нейтрального цвета, метки нет.
  На обратной стороне ru_fr показывается метка рода. В режиме ввода (без переворота) до
  проверки карточка `gender-none`, после — цвет рода.

## R7. Соседи слова в словаре (пункт 1)

- **Decision**: ссылки на слово из списка словаря несут текущие фильтры
  (`?lesson=&topic=&kind=&filter=`). `GET /vocab/{id}` строит тот же список через
  `filter_entries` с этими параметрами, находит позицию, отдаёт `prev`, `next`, `position`,
  `total`; ссылки соседей несут те же параметры. Слово не из списка (например, скрытое при
  фильтре «все») — переходы по полному словарю. Разметка стрелок — как у упражнений
  (`.arrow.prev` / `.arrow.next`).

## R8. Панель букв под полем (пункт 4)

- **Decision**: в `solve.html` панель остаётся одна, но скрыта (`hidden`) и без `sticky`.
  `symbols.js`: при `focusin` на текстовом поле внутри `.solve-form` панель переносится в конец
  `li` этого поля и показывается; при `focusout`, если фокус ушёл не в другое поле формы,
  панель скрывается (кнопки букв не забирают фокус — `mousedown.preventDefault` уже есть).
  Карточки словаря и тренажёры не меняются.

## R9. «Рядом» по умолчанию и без ссылок «… к упражнению» (пункт 9)

- **Decision**: убрать `📖 Текст к упражнению` и `📘 Теория к упражнению` из `solve.html`.
  В `element.html` при загрузке, если `matchMedia("(min-width: 900px)")`, открыть «рядом»
  текст (если есть), иначе теорию — тем же HTMX-запросом, что кнопка. В шапку панели
  добавить ссылку «Открыть отдельной страницей» на `/elements/{shown}`.

## R10. Картинка у всех упражнений (пункт 10)

- **Decision**: блок картинки выводится, если у первого источника файл-картинка
  (`.jpg .jpeg .png .webp .gif`). Начальное состояние Alpine `picture` = `show_source`.
  Класс сетки `with-source` ставится только при открытой картинке (`:class`), чтобы
  свёрнутая не занимала колонку. Подпись кнопки: «Показать картинку» / «Свернуть картинку».

## R11. Сообщение «Не согласна с ответом» (пункт 7)

- **Причина** (проверено по коду): `create_report` вызывает `_element` → `load_content`
  (полное чтение хранилища ≈ 3 с), затем `git commit` и `git push` (до таймаута) — всё
  синхронно, без индикатора; подтверждение выводится в общем `notice` внизу формы,
  `<details>` закрывается после замены разметки. Пользователь видит «ничего не происходит».
- **Decision**:
  - кнопка с `hx-indicator` / `hx-disabled-elt`: «Отправляю…» сразу;
  - маршрут проверяет упражнение по уже загруженному индексу и передаёт в `create_report`
    флаг «элемент проверен» — без `load_content`;
  - ответ рисует подтверждение внутри `item-actions` этого пункта
    (`report_notice = {item_id: текст}`) и оставляет пункт видимым;
  - у пунктов с открытыми сообщениями (`index.reports()` по `element` и `item`) — метка
    «✉ сообщение отправлено» (сразу после отправки — по `item_id` ответа);
  - пустой комментарий — подсказка у пункта, без записи.
- **Alternatives**: отправка на GitHub в фоне — меняет общий механизм записи; отложено.

## R12. Классная работа выполнена (пункт 12)

- **Decision**: функция `exercise_done(e, progress)` = `e.part == "class" or
  progress.is_done(e.id)`; используется в `lessons.py` (список заданий) и
  `ContentIndex.lesson_tree`. Сводка урока и «Сегодня» считают только домашку — без изменений.
  Подпись для классной: «✓ выполнено» (как у прочих).
