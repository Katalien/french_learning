# Research: Формат, хранилище и просмотр уроков

Фаза 0 плана. Для каждого открытого вопроса — решение, обоснование, рассмотренные
альтернативы. Неясностей (`NEEDS CLARIFICATION`) в Technical Context не осталось.

## R1. Формат файлов контента

- **Decision**: структурированные элементы (урок, упражнение, лексика, темы, сообщения
  об ошибках) — YAML; теория и тексты — Markdown с YAML-шапкой (front matter). Один элемент —
  один файл.
- **Rationale**: YAML читается и правится человеком (конституция V, VI: «читаемые файлы»),
  хорошо генерируется агентом, даёт аккуратные git-диффы. Markdown естественен для
  форматированной теории с таблицами. Один файл на элемент — точечные коммиты и откат,
  переклассификация файла в 002 затрагивает только его элементы.
- **Alternatives**: JSON (хуже читается, нет комментариев); всё в SQLite (не читается
  человеком, нет истории git, агенту сложнее); один большой файл на урок (конфликтные
  диффы, хрупкость — одна ошибка портит весь урок).

## R2. Где хранятся правки из интерфейса

- **Decision**: приложение правит те же файлы контента (дата урока, темы элемента,
  переименование / объединение тем, «проверено», сообщения об ошибках) атомарной записью
  (временный файл + замена) и делает git-коммит в репозитории контента с понятным
  сообщением. Отправка на GitHub — вместе с ежедневной копией (функция 003) или агентом.
- **Rationale**: единственный источник правды; агент при следующей обработке видит
  переименованные темы (002 FR-022) и сообщения об ошибках (002 FR-042); откат — через git
  (конституция VI).
- **Alternatives**: «надстройка» правок в SQLite — два источника правды, агент не видит
  правок; правки только через агента — противоречит FR-012–FR-014.

## R3. Где хранятся сообщения об ошибках

- **Decision**: файлы YAML в `reports/` репозитория контента.
- **Rationale**: их мало; агент читает их без специальных инструментов; история в git.
- **Alternatives**: SQLite — агенту нужен скрипт для чтения; в 001 SQLite иначе не нужна.

## R4. База данных в 001

- **Decision**: не используется. Счётчик «выполнено домашки» берётся из интерфейса
  `progress.py`, который в 001 возвращает 0; в 004 он будет читать попытки из SQLite.
  Переключатель происхождения хранится в cookie браузера.
- **Rationale**: конституция XI (простота) — не строим то, что не нужно функции.
- **Alternatives**: завести SQLite сразу — лишняя сложность без данных.

## R5. Разметка пропусков в упражнениях

- **Decision**: пропуск в тексте пункта — `{{N}}` (N — номер пропуска в пункте);
  ответы — словарь `N → список допустимых ответов`.
- **Rationale**: не встречается во французском тексте, легко генерируется агентом, легко
  разбирается; поддерживает несколько пропусков в предложении.
- **Alternatives**: `___` (неразличимы при нескольких пропусках); отдельные поля
  «до / после пропуска» (неудобно при нескольких пропусках).

## R6. Идентификаторы

- **Decision**: `{префикс}-{8 символов base32}` (например, `ex-7kq2m9pd`), префиксы: `les`,
  `th`, `tx`, `ex`, `voc`, `top`, `rep`. Генерируются при создании и не меняются. Номер
  упражнения во вкладке — отдельное поле, не часть идентификатора.
- **Rationale**: стабильны при перенумерации и переклассификации (002 FR-037); короткие
  и читаемые.
- **Alternatives**: UUID (длинные); человекочитаемые слаги (меняются при правке названия).

## R7. Загрузка и обновление контента

- **Decision**: при запуске приложение читает весь контент, проверяет схему и строит индекс
  в памяти. Перед каждым запросом страницы сравнивается «отпечаток» дерева файлов (время
  изменения); при изменении индекс перестраивается.
- **Rationale**: объём мал (тысячи файлов, миллисекунды); агент может добавить урок, пока
  приложение открыто, — обновление без перезапуска.
- **Alternatives**: наблюдатель файловой системы (лишняя зависимость); перезапуск вручную
  (неудобно).

## R8. Отображение Markdown и безопасность

- **Decision**: markdown-it-py с таблицами; результат очищается nh3 (разрешённые теги:
  заголовки, списки, таблицы, выделения, изображения из хранилища).
- **Rationale**: контент пишет агент, но очистка защищает от случайной вставки активного
  HTML; nh3 быстрый и поддерживается.
- **Alternatives**: python-markdown (хуже поддержка таблиц в строгом режиме); без очистки
  (риск).

## R9. «Открыть оригинал»

- **Decision**: изображения и PDF отдаются из папки `sources/` хранилища и открываются
  в браузере; docx показывается как HTML через mammoth (без Word и без интернета). Путь
  к файлу проверяется: отдаются только файлы внутри хранилища.
- **Rationale**: браузер не показывает docx; mammoth работает локально.
- **Alternatives**: конвертация docx в PDF (нужен LibreOffice); только скачивание (неудобно).

## R10. Аудио и видео

- **Decision**: в уроке показывается список медиафайлов с путём к оригиналу и кнопкой
  «Скопировать путь»; открыть файл пользователь может проводником.
- **Rationale**: браузер из соображений безопасности не открывает локальные файлы по ссылке
  `file://` со страницы сервера; копирование пути — надёжно и просто.
- **Alternatives**: отдавать медиа с сервера (копирование больших файлов в хранилище — FR-006
  запрещает).

## R11. Интерфейс без сборки

- **Decision**: Jinja2 + HTMX (частичная подгрузка: вкладки, раскрытие справки, действия) +
  Alpine.js (локальное состояние: переключатели, раскрывающиеся блоки) + Pico CSS (базовые
  стили, адаптивность) + свой небольшой CSS. Файлы библиотек закреплённых версий лежат
  в `static/vendor/` с лицензиями.
- **Rationale**: конституция (стек, IX — без интернета); нет Node.js и шага сборки.
- **Alternatives**: SPA-фреймворк (нужен Node.js — отклонено при выборе стека).

## R12. Инфраструктура качества

- **Decision**: `pre-commit` (через uv) — ruff check и ruff format на коммит, pytest
  на push; GitHub Actions — `uv sync`, ruff, pytest на каждый push и pull request; в CI —
  проверка, что в репозитории нет файлов контента (по расширениям и путям-исключениям).
- **Rationale**: конституция, раздел «Контроль качества»; защита принципа VI.
- **Alternatives**: самописные git-хуки (сложнее поддерживать); только CI (ошибки ловятся
  поздно).

## R13. Тестовые данные

- **Decision**: в `tests/fixtures/content/` — синтетический урок-образец, придуманный
  с нуля (свои предложения и слова), покрывающий все типы упражнений, теорию с таблицей,
  текст, лексику, справку, медиафайл, повреждённый элемент (два демо-урока с общей темой).
  Для ручной проверки по quickstart этот же образец копируется в отдельное демо-хранилище
  (решение пользователя: принимать 001 на придуманном образце, настоящие уроки — в 002).
- **Rationale**: материалы преподавателя нельзя класть в публичный репозиторий даже как
  тестовые данные (VI).
- **Alternatives**: использовать настоящий урок в тестах — нарушение VI.

## R14. Настройки

- **Decision**: pydantic-settings; значения из переменных окружения и локального `.env`
  (в `.gitignore`); `.env.example` — в репозитории. Настройки: `CONTENT_DIR`, `HOST`
  (по умолчанию `127.0.0.1`), `PORT` (по умолчанию `8000`), `SOURCE_MATERIALS_DIR`
  (для путей медиафайлов, только чтение).
- **Rationale**: конституция — пути настраиваются, секреты не коммитятся.
