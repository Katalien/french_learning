# Implementation Plan: Формат, хранилище и просмотр уроков

**Branch**: `001-lesson-content-view` | **Date**: 2026-09-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-lesson-content-view/spec.md`

## Summary

Первая функция с кодом: закладывает проект целиком. Создаётся веб-приложение на Python
(FastAPI + серверные шаблоны + HTMX/Alpine.js), которое читает учебный контент из приватного
git-репозитория `french_learning_materials` и показывает его: список уроков со сводками,
урок с разделами «Теория», «Тексты», «Задания» (вкладки «В классе» / «Домашка»), темы,
«Дополнительные материалы», происхождение, пометки «требует проверки», сообщения об ошибках.

Главный артефакт функции — **формат контента** ([contracts/content-format.md](contracts/content-format.md)):
YAML-файлы для структурированных элементов и Markdown с YAML-шапкой для теории и текстов.
Схема формата описана в коде один раз (модели pydantic) и используется и приложением при
загрузке, и командой проверки контента, которую будет вызывать агент (функция 002).
Правки из интерфейса (дата урока, темы, «проверено», сообщения об ошибках) записываются
в те же файлы контента с автоматическим git-коммитом — файлы остаются единственным
источником правды. Базы данных в этой функции нет: прогресс появится в 003/004.

Также в функции настраивается инфраструктура проекта: тесты, линтер, git-хуки, CI, README,
CHANGELOG, настройки через локальный файл, исключённый из git.

## Technical Context

**Language/Version**: Python 3.12 (управление — `uv`)

**Primary Dependencies**: FastAPI, Uvicorn, Jinja2, pydantic v2 + pydantic-settings,
PyYAML, markdown-it-py (+ плагины таблиц), nh3 (очистка HTML), mammoth (просмотр docx);
в браузере — HTMX, Alpine.js, Pico CSS (хранятся в проекте локально)

**Storage**: файлы контента (YAML + Markdown + сжатые копии исходников) в приватном
git-репозитории, путь — настройка `CONTENT_DIR`; в этой функции SQLite не используется

**Testing**: pytest (+ httpx/TestClient для страниц), синтетический контент-образец
в `tests/fixtures/`; ручная проверка интерфейса по [quickstart.md](quickstart.md)

**Target Platform**: локальный веб-сервер на Windows 11, браузер на компьютере; вёрстка
пригодна для экрана телефона (375 px)

**Project Type**: веб-приложение с серверным рендерингом (один проект)

**Performance Goals**: страницы открываются мгновенно для пользователя (< 300 мс на локальной
машине) при объёме до ~200 уроков и ~20 000 элементов

**Constraints**: без интернета; слушает только 127.0.0.1; ни один файл контента не попадает
в публичный репозиторий; повреждённый элемент не ломает остальные

**Scale/Scope**: 1 пользователь; ~100 уроков в год; ~15 экранов/фрагментов

└── web/

    ├── routes/             # lessons, topics, extras, elements, reports, sources
    ├── templates/          # Jinja2: base, home, lesson, topic, extras, partials/*
    └── static/
        ├── css/app.css

tests/
├── fixtures/content/       # синтетический контент-образец (придуманный, не материалы)

**Structure Decision**: один проект Python с пакетом в `src/` (стандартная раскладка для uv);
веб-слой отделён от слоя контента, чтобы функция 002 (агент) могла использовать `content/`
без веб-сервера — через команду `validate-content`.
