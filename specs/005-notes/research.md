# Research: Заметки (005)

Решения по неясным местам плана. Формат: решение → почему → что ещё рассматривали.

## R1. Где хранить заметки

**Решение**: новая таблица `notes` в базе прогресса (`CONTENT_DIR/.progress/progress.sqlite`),
версия схемы 2 → 3. Миграция только добавляет таблицу (как 003 → 004). Резервная копия
`backups/progress.sql` подхватывает таблицу сама: `dump()` выгружает всю базу.

**Почему**: так решил пользователь — «отдельно от материалов, но с резервной копией»
(FR-018). База прогресса уже лежит вне git-хранилища материалов (`.progress/` в
`.gitignore`), а ежедневная копия уходит в приватный репозиторий. Заметки — личные данные,
как ответы и прогресс (принцип VI).

**Отвергнуто**: YAML-файлы рядом с уроками — смешиваются с материалами, и агент при
переобработке урока может их задеть. Отдельный файл SQLite — второй механизм копирования
без пользы.

## R2. Как привязывать заметку к фрагменту

**Решение**: якорь по цитате (как `TextQuoteSelector` в W3C Web Annotation) плюс подсказка
по позиции:
- `exact` — выделенный текст;
- `prefix` / `suffix` — до 32 символов слева и справа;
- `start` — смещение в тексте элемента на момент создания.

Поиск при открытии страницы:
1. все вхождения `exact` в тексте контейнера элемента (с пробелами, сжатыми до одного);
2. если вхождений несколько, выбирается то, у которого больше совпадают `prefix`/`suffix`;
   при равенстве — ближайшее к `start`;
3. если вхождений нет, якорь «не найден»: заметка показывается у элемента с пометкой
   «место не найдено» (уточнение 2026-09-29) и её можно привязать заново.

**Почему**: переобработка урока меняет разметку и номера абзацев, а текст фразы обычно
остаётся. Цитата с контекстом переживает такие правки, а смещение надёжно различает
повторы одной фразы.

**Отвергнуто**:
- XPath/CSS-путь до узла — ломается от любой правки разметки;
- только смещение — ломается от любой правки текста выше;
- метки прямо в файлах контента — смешивают личные данные с материалами (VI).

## R3. Где искать якорь и как его показывать

**Решение**: поиск и подсветка — в браузере, в небольшом модуле `static/js/notes.js`
(обычный JavaScript, без сборки, как `speech.js`). Найденный диапазон оборачивается в
`<mark class="note-anchor" data-note="…">`. Если диапазон пересекает несколько текстовых
узлов, оборачивается каждый кусок.

Контейнеры элементов:
- страница элемента — тело текста или теории и область упражнения (условие и пункты);
- разделы урока «Теория» и «Тексты» — каждая статья `article#<id элемента>`;
- панель «Теория рядом» — фрагмент, который HTMX подгружает в упражнение: после
  `htmx:afterSwap` якоря расставляются заново.

**Почему**: окончательный текст (Markdown в HTML, разметка упражнения) есть только
в браузере. Сервер отдаёт заметки как JSON на странице, браузер их расставляет.

**Отвергнуто**:
- вставка `<mark>` на сервере — пришлось бы повторять разбор HTML всех шаблонов упражнений;
- CSS Custom Highlight API — подсветка не ловит щелчки, а нужен щелчок по фрагменту.

**Проверка**: логика поиска (сжатие пробелов, выбор вхождения) написана отдельными чистыми
функциями. Их проверяет раздел quickstart «Якоря» на подготовленном тексте с повторами
и правкой. Автотестов JS в проекте нет (принцип XIII: интерфейс проверяется по quickstart).
Серверная часть — API, хранение, группировка — пишется по TDD.

## R4. Как интерфейс работает с сервером

**Решение**:
- заметки нужных элементов встраиваются в страницу:
  `<script type="application/json" id="notes-data">`;
- изменения идут через небольшой JSON API (`contracts/notes-api.md`):
  `POST /notes`, `PATCH /notes/{id}`, `DELETE /notes/{id}`;
- `notes.js` после ответа сервера перерисовывает поле и отметки без перезагрузки;
- страница «Заметки к уроку» и панель вопросов отрисовываются на сервере (Jinja).
  Действия на них идут через тот же API, после чего блок перезагружается через HTMX
  (`?fragment=1`).

**Почему**: поле заметок раскладывается по высоте строк — это всё равно делается в JS.
Отдавать JSON проще и точнее, чем HTML-куски для каждого варианта показа. Страница урока
и панель вопросов — обычные списки, их проще собрать на сервере.

**Отвергнуто**: всё на HTMX с HTML-ответами — раскладка по строкам и отметки фрагментов
всё равно требуют JS.

## R5. Подсказка при выделении — общая с 006

**Решение**: общий модуль `static/js/selection.js`. Он показывает маленькую панель у
выделения в контейнерах элементов, и в неё добавляются «секции». В 005 секция одна —
«пометка · вопрос» (полоска из двух значков, уточнение v7). Функция 006 добавит сверху
секцию перевода. Когда перевод выключен, остаётся полоска — это уже решено в
спецификации 005.

На сенсорном экране панель появляется, когда выделение не меняется около 0,6 с
(`selectionchange`).

**Почему**: по новому порядку работы (005 → 006 → 007) подсказку при выделении впервые
делают заметки. Если сразу сделать её расширяемой, 006 не придётся переделывать код.

## R6. Значки

**Решение**: SVG-спрайт прямо в `base.html` (`<symbol id="i-note">`, `<symbol id="i-question">`),
нарисованный по набору «облачка-комментарии» из v7. Используется через
`<svg class="icon"><use href="#i-note"/></svg>`; цвет — `currentColor` из токенов
(пометка — лавандовый `--primary-strong`, вопрос — голубой).

**Почему**: значки собственные, лицензий не нужно, файлов не прибавляется, работает без
интернета. Цвет меняется вместе со светлой и тёмной темой.

## R7. Урок у заметки и «осиротевшие» заметки

**Решение**: у заметки всегда хранится номер урока. У заметки к элементу хранится ещё
`element_id` и копия названия элемента на момент записи (`element_title`). Если элемент
пропал из урока, заметка показывается в блоке «К уроку» с пометкой «было: <название>»
(edge case спецификации).

Заметки бывают только у элементов уроков: у дополнительных материалов их нет
(уточнение 2026-09-29).

## R8. Счётчик «❓ N» в шапке

**Решение**: `nav_counts()` получает поле `questions` — это один `select count(*)` по
индексу `(kind, answered)`. Значок показывается, только если N > 0. Панель вопросов
загружается через HTMX по щелчку (`GET /questions`), а не при каждой загрузке страницы.

## R9. Правка и Enter

**Решение**:
- Enter сохраняет, Shift+Enter переносит строку, Esc отменяет — одно правило для всех полей
  заметок, реализовано в `notes.js`;
- если в правке вопроса заполнен ответ, сервер ставит `answered = 1`
  (FR-006; проверяется тестом API);
- если отметку «отвечен» снять, ответ сохраняется.
