# Data Model: Навык агента для добавления уроков

Сущности контента — как в [001/data-model.md](../001-lesson-content-view/data-model.md).
Здесь — дополнения и служебные сущности функции 002.

## Журнал файлов урока — поле `files` в `lesson.yaml` (дополнение формата v1)

| Поле | Тип | Правила |
|---|---|---|
| `path` | str | путь относительно папки материалов пользователя (`Leçon 14/Devoirs/IMG_3874.jpeg`) |
| `part` | Part | `class` / `homework` |
| `sha256` | str (64 hex) | хеш содержимого при обработке |
| `classification` | `theory` · `vocabulary` · `text` · `exercises` · `exercises_with_reference` · `media` · `duplicate` · `unrecognized` · `skipped` | |
| `elements` | список Id | элементы, созданные из файла (для переклассификации) |
| `stored_as` | str? | путь сжатой копии в хранилище (`lessons/014/sources/…`) |
| `note` | str? | причина пропуска / «не распознан» / «дубль файла X» |

**Правила**: `path` уникален в пределах урока; каждый id из `elements` существует; для
`media` — `stored_as` пусто, запись есть и в `media`; для `duplicate` / `unrecognized` /
`skipped` — `note` обязателен.

**Состояния файла при повторном запуске** (вычисляются `scan-lesson`): `new` (нет в журнале),
`processed` (хеш совпадает), `changed` (путь есть, хеш другой), `missing` (в журнале есть,
на диске нет).

## Черновик операции — `CONTENT_DIR/.staging/<op-id>/`

Та же структура, что у хранилища (`lessons/NNN/...`, `vocabulary/...`, `topics.yaml`,
`extra/...`). Файлы черновика **заменяют или добавляют** файлы хранилища. Удаление
элемента — файл-список `.staging/<op-id>/_delete.txt` (пути относительно хранилища).
`commit-staging` применяет всё целиком или ничего. Папка `.staging/` — в `.gitignore`
хранилища.

## Опись для пользователя (в чате, не хранится)

По каждому файлу: номер, путь, часть, классификация, будущие элементы (для упражнений —
предлагаемые номер, тема, описание, тип), вопросы по крупным сомнениям. Формат —
[contracts/skill-workflow.md](contracts/skill-workflow.md).

## Отчёт об обработке (в чате, не хранится)

Итог по каждому файлу; число элементов по видам; «требует проверки» (элемент, пункт,
причина); новые темы; новые типы упражнений; результат коммита и отправки.

## Опись урока — `lessons/NNN/inventory.md` (генерируется)

Шапка: номер, дата, темы урока. Таблицы «В классе» / «Домашка»: исходный файл →
классификация → элементы (номер, тема, описание) → сжатая копия; «Аудио и видео»: имя →
путь к оригиналу; «Пропущено»: файл → причина.

## Общий указатель — `index.md` (генерируется)

Список уроков (номер, дата, темы, число упражнений и слов); список тем по разделам
со ссылками на уроки, где тема встречается.

## Сообщение об ошибке — дополнение к 001

`status`: `open` → `fixed` | `rejected`; `resolution` — пояснение агента (обязательно
при закрытии); `resolved` — дата-время закрытия (новое необязательное поле).
