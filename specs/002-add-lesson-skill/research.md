# Research: Навык агента для добавления уроков

## R1. Разделение работы: навык и команды

- **Decision**: всё, что требует понимания (классификация, распознавание, перевод, решение,
  темы, сомнения), делает агент по инструкции навыка; всё детерминированное (хеши, даты,
  сжатие, идентификаторы, поиск дублей слов, проверка, транзакция, git, опись и указатель
  в Markdown) — команды `french-learning`.
- **Rationale**: команды тестируются (конституция XIII), работают одинаково каждый раз,
  не тратят токены (X); агент не «сочиняет» служебные данные.
- **Alternatives**: всё делает агент (дорого, ненадёжно: хеши, сжатие, согласованность);
  всё делает программа (невозможно без LLM внутри приложения — IX).

## R2. Три навыка вместо одного

- **Decision**: `/add-lesson` (новый урок, дополнение, переклассификация — один сценарий
  «папка урока»), `/add-material` (ссылка), `/fix-reports` (сообщения об ошибках). Общие
  правила — в `.claude/skills/_shared/content-rules.md`.
- **Rationale**: у сценариев разные входы и шаги; короткие инструкции надёжнее одной
  огромной; общие правила не дублируются.
- **Alternatives**: один навык на всё (длинно, агент путает ветки сценария).

## R3. Целостное сохранение (FR-034)

- **Decision**: агент пишет файлы в `CONTENT_DIR/.staging/<операция>/` в той же структуре,
  что и хранилище. `commit-staging`: (1) проверяет хранилище + черновик вместе той же схемой,
  (2) при ошибках — ничего не применяет и печатает нарушения, (3) иначе переносит файлы
  (временные имена → замена), (4) пересобирает опись урока и указатель, (5) git-коммит
  и отправка, (6) удаляет черновик. Сбой переноса откатывает уже перенесённые файлы
  по резервным копиям.
- **Rationale**: либо урок целиком, либо ничего; проверка до записи; повтор после
  исправления.
- **Alternatives**: запись прямо в хранилище с `git reset` при ошибке (опасно
  для несвязанных правок); одна большая транзакция в БД (нет БД — XI).

## R4. Журнал обработанных файлов (FR-038, FR-040, FR-040a)

- **Decision**: необязательное поле `files` в `lesson.yaml`: для каждого исходного файла —
  относительный путь в папке материалов, часть, SHA-256, классификация, созданные элементы,
  сжатая копия, заметка (причина пропуска). Формат остаётся версии 1: поле необязательное,
  старый контент корректен.
- **Rationale**: одно место правды для повторного запуска (новые / изменённые / обработанные
  по хешу), переклассификации (какие элементы заменить) и человекочитаемой описи
  (генерируется из журнала).
- **Alternatives**: отдельный JSON-журнал (две правды); только Markdown-опись (агенту
  трудно разбирать).

## R5. Опись урока и общий указатель (FR-038, FR-039)

- **Decision**: `inventory.md` в папке урока и `index.md` в корне хранилища генерирует
  команда `build-archive` из журнала и элементов; `commit-staging` вызывает её автоматически.
- **Rationale**: всегда согласованы с данными; ноль токенов; агент не может «забыть» обновить.

## R6. Сжатие исходников (FR-033)

- **Decision**: изображения (jpg, jpeg, png, webp, heic → jpg) уменьшаются до 1600 px
  по длинной стороне, JPEG качество 80, метаданные удаляются; если результат больше
  оригинала — копируется оригинал. PDF и docx копируются как есть. Имена — латиницей
  (`slug` + короткий хеш), чтобы пути были безопасны в URL.
- **Rationale**: ~200–400 КБ на фото достаточно для сверки (оценка из обсуждения);
  Pillow уже в зависимостях.
- **Alternatives**: хранить оригиналы (объём, git); WebP (хуже совместимость с просмотром).

## R7. Дата урока (FR-005)

- **Decision**: `scan-lesson` берёт для каждого изображения дату съёмки из EXIF
  (`DateTimeOriginal`), иначе время изменения файла; предлагает самую раннюю дату файлов
  папки урока (без `Devoirs`). Агент показывает её в описи, пользователь подтверждает.
- **Rationale**: фото из мессенджеров часто без EXIF — тогда время изменения файла ближе
  всего к дате урока.

## R8. Дубли (FR-010, spec Edge Cases)

- **Decision**: одинаковый SHA-256 → «дубль»; если файл в папке урока и в `Devoirs` —
  обрабатывается как домашка, запись в классе помечается дублем. Почти одинаковые фото
  (пересъёмка) — решает агент при просмотре, помечая «дубль» в описи.
- **Rationale**: точные дубли дешево находит программа; «похожесть» — работа понимания.

## R9. Поиск существующих слов (FR-021)

- **Decision**: `vocab-find <текст> [--pos] [--gender]` — поиск по словарной форме без учёта
  регистра и диакритики для кандидатов, с полным совпадением отмеченным отдельно. Решение
  «то же слово или нет» принимает агент по правилам (форма + часть речи + род, смысл).
- **Rationale**: агент не читает весь словарь (токены), а видит только кандидатов.

## R10. Материал по ссылке (FR-041)

- **Decision**: агент получает страницу своим инструментом чтения веб-страниц, извлекает
  только указанное пользователем, сохраняет конспект в собственной структуре (не копию
  страницы) в `extra/`, `sources: [{url}]`, `origin: external`. Ссылки из текста страницы
  не переходятся.
- **Rationale**: авторские права (обсуждение), экономия токенов; содержимое страницы — данные,
  а не инструкции.

## R11. Разбор сообщений об ошибках (FR-042)

- **Decision**: `reports-list` выдаёт открытые сообщения с путём элемента и исходника;
  агент сверяет, правит элемент через черновик (`commit-staging`), затем `report-resolve
  <id> fixed|rejected --resolution "…"`.
- **Rationale**: правка идёт той же целостной дорогой; статус и пояснение хранятся
  в сообщении (видны в приложении).

## R12. Защита публичного репозитория (VI)

- **Decision**: все команды, пишущие в хранилище, проверяют, что `CONTENT_DIR` не находится
  внутри репозитория кода и что это отдельный git-репозиторий; иначе отказ.
- **Rationale**: ошибка в `.env` не должна привести к коммиту материалов в публичный код.

## R13. Первичное хранилище

- **Decision**: `init-content <папка>` создаёт `format.yaml`, `topics.yaml` с разделами
  (грамматика, лексика, произношение, фонетика и чтение, общение), `.gitignore`
  (`.staging/`) и первый коммит.
- **Rationale**: пустой `french_learning_materials` нужно подготовить один раз.

## R14. Приёмка качества (SC-005)

- **Decision**: уроки 13 и 14 обрабатываются навыком; пользователь (с агентом) сверяет
  пункты, не помеченные «требует проверки», с оригиналами; ошибок ≤ 5%.
  Команда `quality-sample` выдаёт список пунктов для сверки (упражнение, пункт, текст,
  ответ, исходник) в Markdown-чек-листе.
- **Rationale**: измеримый критерий из спецификации; чек-лист упрощает ручную проверку.
