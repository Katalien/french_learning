# Implementation Plan: Навык агента для добавления уроков

**Branch**: `002-add-lesson-skill` | **Date**: 2026-09-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-add-lesson-skill/spec.md`

## Summary

Функция состоит из двух частей, которые делят работу по принципу «думает агент, считает
программа»:

1. **Навыки Claude Code** (инструкции в `.claude/skills/`): `/add-lesson` (урок и дополнение
   урока), `/add-material` (материал по ссылке), `/fix-reports` (разбор сообщений об ошибках).
   Агент читает файлы, классифицирует, распознаёт, переводит формулировки, решает
   упражнения, определяет темы и сомнения — то, что требует понимания.
2. **Вспомогательные команды** `french-learning ...` (Python, тестируемые): опись файлов папки
   с хешами и датами, сжатие исходников, выдача идентификаторов, поиск слов в словаре,
   **транзакционное сохранение урока** (черновик → проверка формата всего хранилища →
   атомарный перенос → git-коммит → отправка), построение описи урока и общего указателя,
   работа с сообщениями об ошибках, создание пустого хранилища. Всё детерминированное
   делает программа — быстрее, надёжнее и без токенов (конституция X).

Агент никогда не пишет напрямую в хранилище: он кладёт файлы в черновик
`.staging/` внутри хранилища, а команда `commit-staging` проверяет всё вместе и применяет
целиком или не применяет вовсе (FR-034).

## Technical Context

**Language/Version**: Python 3.12 (uv); навыки — Markdown-инструкции Claude Code

**Primary Dependencies**: существующие (pydantic, PyYAML, mammoth); Pillow переносится
из dev-зависимостей в основные (сжатие изображений); PDF и docx копируются без изменений

**Storage**: приватный репозиторий `french_learning_materials` (формат 001, версия 1
с дополнением: журнал обработанных файлов в `lesson.yaml`); черновик `.staging/`
(в `.gitignore` хранилища)

**Testing**: pytest для вспомогательных команд (TDD); навыки — приёмочной проверкой
на уроках 13 и 14 (quickstart.md, SC-005)

**Target Platform**: Windows 11, Claude Code в папке проекта

**Project Type**: навыки агента + CLI-команды в существующем проекте

**Performance Goals**: команды — секунды на урок из 15–25 файлов; обработка урока агентом —
одна сессия (SC-001)

**Constraints**: ни один файл контента — в публичный репозиторий; сохранение целостное;
только явно запрошенная работа ИИ

**Scale/Scope**: ~2 урока в неделю, 15–25 файлов каждый

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Принцип | Как соблюдается | Статус |
|---|---|---|
| I. Прослеживаемость | Навык обязан ставить `origin`, `sources`, `instruction.origin`, `answers_origin`; `validate-content` отклоняет элементы без источника | ✅ |
| II. Пользователь определяет состав | Опись перед обработкой; выбор и статусы; неупомянутые — «резерв»; журнал фиксирует пропущенные файлы с причиной | ✅ |
| III. Проверка по исключению | Крупные сомнения — вопросы в описи; мелкие — `needs_review` с пояснением; отчёт; `/fix-reports` | ✅ |
| IV. Интерфейс вместо картинок | Навык превращает материал в типизированные элементы; «по картинке» — исходник рядом | ✅ |
| V. Единый формат | Черновик проверяется той же схемой (`validate-content --with-staging`) до применения; дополнение формата (журнал) описано в контракте | ✅ |
| VI. Разделение данных | Команды отказываются работать, если `CONTENT_DIR` внутри репозитория кода; коммит и отправка только в хранилище | ✅ |
| VII. История | При обновлении изменённого файла идентификаторы сохраняются; истории выполнения пока нет (004) | ✅ |
| VIII. Французский | Правила лексики (словарная форма, род, артикль, h придыхательное) в навыке; `vocab-find` против дублей | ✅ |
| IX. Ядро без сервисов | Приложение не меняется; ИИ работает только в Claude Code | ✅ |
| X. Экономия ИИ | Детерминированное — в командах; навык читает каждый файл один раз; ничего сверх запрошенного | ✅ |
| XI. Простота | Без БД и фоновых процессов; черновик — обычная папка | ✅ |
| XIII. TDD | Все команды — сначала тесты | ✅ |

### Source Code (repository root)

```text
.claude/skills/
├── add-lesson/SKILL.md        # урок из папки, дополнение урока, переклассификация
├── add-material/SKILL.md      # материал по ссылке
├── fix-reports/SKILL.md       # разбор сообщений об ошибках
└── _shared/
    ├── content-rules.md       # правила классификации, типов, лексики, тем, сомнений
    └── report-template.md     # формат описи для пользователя и итогового отчёта

docs/content-format.md         # действующее описание формата (из 001 + журнал), на него
                               # ссылаются навыки и приложение

src/french_learning/
├── cli.py                     # регистрация новых команд
└── agent/                     # вспомогательные команды для навыков
    ├── scan.py                # scan-lesson: опись папки (хеши, даты, типы, дубли, журнал)
    ├── sources.py             # store-source: сжатие изображений, копирование PDF/docx
    ├── ids.py                 # new-ids
    ├── vocab.py               # vocab-find
    ├── staging.py             # stage-check, commit-staging (транзакция + коммит + отправка)
    ├── archive.py             # build-archive: опись урока и общий указатель (Markdown)
    ├── reports.py             # reports-list, report-resolve
    └── storage.py             # init-content, защита от CONTENT_DIR внутри кода

tests/unit/agent/              # тесты каждой команды
tests/fixtures/materials/      # синтетические «исходные материалы» (придуманные)
```

**Structure Decision**: вспомогательные команды — отдельный пакет `agent/` в существующем
проекте: они используют схему и загрузчик из `content/`, а веб-приложение от них
не зависит.
