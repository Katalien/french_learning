# Feature Specification: Навык агента для добавления уроков

**Feature Branch**: `002-add-lesson-skill`

**Created**: 2026-09-26

**Status**: Draft

**Input**: Описание пользователя (собрано из обсуждения): «После урока я открываю Claude Code
и говорю агенту: вот папка урока, добавь. Агент по инструкции разбирает фото, PDF и документы:
отделяет теорию, лексику, тексты и упражнения, переводит формулировки заданий на русский,
решает упражнения, проверяет себя и сохраняет всё в формате, который показывает приложение.
Я могу сказать, какие задания добавить, а какие отложить в резерв или сделать
необязательными. В конце агент отчитывается, что добавил, что пропустил и в чём не уверен.
Так же можно добавить материал по ссылке из интернета.» Подробности — в `docs/roadmap.md`,
функция 002; формат контента — в `specs/001-lesson-content-view/spec.md`.

## Границы функции

- **Входит**: инструкция (навык) агента Claude Code для обработки материалов урока
  и материалов по ссылке; классификация файлов; разделение файлов на элементы; перевод
  формулировок; решение упражнений; извлечение лексики; самопроверка; сохранение
  в хранилище контента в формате функции 001; отчёт; повторная обработка урока (дополнение);
  исправление контента по сообщениям об ошибках.
- **Не входит**: просмотр контента (001), экран ручного добавления слов (003), выполнение
  упражнений (004), генерация новых упражнений агентом по запросу (запланирована
  в функции 004 — навык агента, который создаёт упражнения на заданную тему), обработка аудио и видео
  (веха 4), подготовка переводов текстов для чтения (веха 4).

## Clarifications

### Session 2026-09-26

- Q: Если пользователь указал только часть упражнений («добавь 1 и 3»), что делать
  с остальными? → A: Добавлять со статусом «резерв» (скрыты из списков урока, доступны
  в «Резерве»).
- Q: Что делать с картинками внутри теории? → A: Где возможно — превращать в текст (таблицы,
  примеры); где нельзя передать текстом — вставлять изображение в теорию; декоративные
  картинки — отбрасывать.

### Session 2026-09-27

- Q: Как агенту сохранять изменения в приватном репозитории контента после обработки урока?
  → A: Автоматически: коммит с понятным сообщением и отправка в приватный репозиторий
  на GitHub, без отдельного подтверждения.
- Q: Когда агент не уверен во время обработки, спрашивать сразу или ставить пометку? → A:
  Крупные сомнения (как понять файл, как разрезать лист, тема) — вопросом в описи
  до обработки; мелкие (слово, ответ, тип упражнения) — пометкой «требует проверки» без
  вопросов.
- Q: Что делать, если при повторном запуске уже обработанный файл изменился? → A: Показать
  в описи, что файл изменился и что именно поменялось; пользователь решает: обновить элементы
  (с сохранением статусов и истории), добавить как новые или пропустить.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Добавить урок из папки материалов (Priority: P1)

Пользователь пишет агенту команду с путём к папке урока (например, `Leçon 15`) и, по желанию,
указаниями: темы урока, какие задания добавить и с каким статусом. Агент изучает все файлы
папки и её подпапки `Devoirs`, показывает пользователю опись найденного (теория, лексика,
тексты, упражнения с кратким описанием, медиафайлы, дубли), уточняет дату урока и выбор
заданий, затем обрабатывает материал и сохраняет урок. Урок сразу появляется в приложении.

**Why this priority**: без наполнения приложение пусто; это основной способ получения
контента.

**Independent Test**: выполнить команду для папки `Leçon 14` → получить опись → подтвердить
выбор → открыть приложение и увидеть урок 14 с теорией, текстом «Au restaurant», заданиями
«В классе» и «Домашка» и лексикой.

**Acceptance Scenarios**:

1. **Given** пользователь указал путь к папке урока, **When** агент изучил файлы, **Then** он
   показывает опись: для каждого файла — как он классифицирован (теория, лексика, текст, лист
   упражнений, лист упражнений со справкой, медиафайл, дубль, не распознан) и какие элементы
   из него получатся; для упражнений — предлагаемый номер, тема и краткое описание.
2. **Given** опись показана, **When** пользователь отвечает «добавь всё» или указывает выбор
   («добавь 1 и 3, второе — в резерв, пятое — необязательное»), **Then** агент добавляет
   упражнения с указанными статусами; если выбор указан, неупомянутые упражнения добавляются
   со статусом «резерв»; если выбора нет («добавь всё»), все упражнения — основные.
3. **Given** номер урока указан в имени папки (`Leçon 15`), **When** агент создаёт урок,
   **Then** номер урока — 15; дату агент предлагает по датам файлов, и пользователь её
   подтверждает или исправляет.
4. **Given** файл лежит и в папке урока, и в `Devoirs`, **When** агент его обрабатывает,
   **Then** элементы из него добавляются один раз и относятся к домашке.
5. **Given** обработка завершена, **When** пользователь открывает приложение, **Then** урок
   виден в списке уроков, и контент проходит проверку формата без ошибок.

### User Story 2 - Правильно разобрать материал (Priority: P1)

Агент превращает каждый файл в элементы контента по правилам: теория — из файлов теории,
справка на листе упражнений прикрепляется к упражнению, один лист может дать несколько
упражнений, текст для чтения становится отдельным элементом, лексика извлекается из файлов
лексики, у каждого упражнения — тип, формулировка на русском с сохранённым оригиналом
и правильные ответы.

**Why this priority**: качество разбора определяет ценность всего приложения; входит в P1
вместе с историей 1.

**Independent Test**: обработать урок 14 и сверить результат с оригиналами: лист `IMG_3874`
дал 4 упражнения; лист `IMG_3765` — упражнение со справкой (таблица партитивов); `IMG_3864`
— текст «Au restaurant» и 2 упражнения к нему; `IMG_3334` — упражнение «по картинке»
с исходным файлом.

**Acceptance Scenarios**:

1. **Given** файл, в котором объяснения занимают большую часть, лежит в папке урока и назван
   по теме, **When** агент классифицирует его, **Then** он становится теорией
   с форматированным текстом (заголовки, таблицы, примеры).
2. **Given** лист, где основная часть — пронумерованные задания, а сверху короткая таблица,
   **When** агент его разбирает, **Then** получаются упражнения, а таблица прикрепляется
   к ним как справка.
3. **Given** справка на листе упражнений содержит тему, которой нет в теории урока, **When**
   агент её разбирает, **Then** она добавляется как элемент теории.
4. **Given** на одном листе несколько упражнений, **When** агент его разбирает, **Then**
   каждое упражнение становится отдельным элементом со своим типом и номером на листе.
5. **Given** упражнение, **When** агент его сохраняет, **Then** формулировка переведена
   на русский (оригинал сохранён), пункты — на французском, у каждого пропуска один или
   несколько допустимых правильных ответов с пометкой «решено ИИ».
6. **Given** упражнение подходит под тип «открытый ответ», **When** агент его сохраняет,
   **Then** правильные ответы не создаются.
7. **Given** упражнение основано на картинке, **When** агент его сохраняет, **Then** тип
   «по картинке», исходный файл прикреплён для показа рядом.
8. **Given** на фото есть пометки или ответы, **When** агент разбирает лист, **Then**
   пометки игнорируются, упражнение считается невыполненным.
9. **Given** файл лексики урока, **When** агент его разбирает, **Then** каждое слово становится
   лексической единицей с переводом, словарной формой, а у существительных — с родом
   и артиклем; слово, уже существующее в хранилище, не дублируется, а связывается с уроком.
10. **Given** в папке аудио- или видеофайлы, **When** агент обрабатывает урок, **Then** они
    не обрабатываются, но записываются в урок как медиафайлы.

### User Story 3 - Получить честный отчёт (Priority: P2)

После обработки агент выдаёт отчёт: что добавлено (по разделам), что пропущено и почему,
какие элементы помечены «требует проверки» и почему, какие темы созданы, какие файлы
не распознаны. Пользователь может поправить классификацию («IMG_3765 — это теория»),
и агент переделывает соответствующие элементы.

**Why this priority**: реализует принципы «проверка по исключению» и «ничего не
отбрасывается молча».

**Independent Test**: обработать урок, где один файл заведомо нечитаем → в отчёте он указан
как «не распознан» с причиной; попросить переклассифицировать файл → элементы пересозданы.

**Acceptance Scenarios**:

1. **Given** обработка завершена, **When** агент выдаёт отчёт, **Then** в нём перечислены
   все файлы папки, каждый — с итогом (добавлен как …, пропущен по причине …, не распознан).
2. **Given** агент не уверен в распознанном слове или правильном ответе, **When** он сохраняет
   элемент, **Then** элемент помечен «требует проверки» с указанием, что именно под
   сомнением, и перечислен в отчёте.
3. **Given** пользователь не согласен с классификацией файла, **When** он просит
   переклассифицировать, **Then** агент удаляет элементы, созданные из этого файла,
   и создаёт новые по указанию; идентификаторы остальных элементов не меняются.

---

### User Story 4 - Дополнить уже добавленный урок (Priority: P2)

Домашка или дополнительные материалы могут появиться после того, как урок уже добавлен.
Пользователь запускает команду для той же папки снова; агент находит только новые
и изменённые файлы и добавляет их, не трогая уже обработанное.

**Why this priority**: материалы часто приходят частями; повторная полная обработка тратит
токены и ломает связи.

**Independent Test**: добавить урок без папки `Devoirs` → положить файлы в `Devoirs` →
запустить команду снова → добавились только упражнения домашки, нумерация продолжилась,
прежние элементы не изменились.

**Acceptance Scenarios**:

1. **Given** урок уже добавлен, **When** команда запускается для той же папки, **Then** агент
   сообщает, какие файлы новые, и обрабатывает только их.
2. **Given** в уроке уже есть упражнения домашки 1–3, **When** добавляются новые, **Then**
   их сквозная нумерация продолжается с 4.
3. **Given** урок 15 уже добавлен без домашки, **When** пользователь пишет «добавь домашку
   к уроку 15» (с путём к файлам или без — тогда берётся `Leçon 15/Devoirs`), **Then** агент
   показывает опись новых файлов и после подтверждения добавляет их в домашку урока 15.
4. **Given** уже обработанный файл заменён исправленной версией с тем же именем, **When**
   команда запускается снова, **Then** агент показывает в описи, что файл изменился и что
   поменялось, и предлагает обновить, добавить как новое или пропустить; при обновлении
   статусы упражнений и история выполнения сохраняются.

---

### User Story 5 - Добавить материал по ссылке (Priority: P3)

Пользователь даёт агенту ссылку на страницу в интернете и указывает, что взять (например,
«правило про passé composé»). Агент добавляет материал как элементы без урока, с ссылкой
на источник и темой; они появляются в «Дополнительных материалах» и в теме.

**Why this priority**: полезное дополнение; основной поток — материалы уроков.

**Independent Test**: дать ссылку на страницу с правилом → в «Дополнительных материалах»
появился элемент теории с происхождением «внешний ресурс» и ссылкой.

**Acceptance Scenarios**:

1. **Given** пользователь дал ссылку и указание, **When** агент обрабатывает страницу,
   **Then** создаются элементы без урока с происхождением «внешний ресурс», ссылкой и темой
   из справочника.
2. **Given** страница недоступна, **When** агент пытается её открыть, **Then** он сообщает
   об этом и ничего не сохраняет.

---

### User Story 6 - Исправить контент по сообщениям об ошибках (Priority: P3)

Пользователь просит агента разобрать накопившиеся сообщения об ошибках из приложения. Агент
по каждому сообщению сверяется с оригиналом, исправляет элемент или объясняет, почему
исправление не нужно, и отмечает сообщение закрытым.

**Why this priority**: замыкает цикл качества; до накопления сообщений не нужно.

**Independent Test**: оставить в приложении сообщение «неверный ответ в пункте 3» → попросить
агента разобрать сообщения → ответ исправлен, сообщение закрыто, агент кратко объяснил
исправление.

**Acceptance Scenarios**:

1. **Given** есть открытые сообщения об ошибках, **When** пользователь просит их разобрать,
   **Then** агент по каждому сверяется с оригиналом и либо исправляет элемент, либо объясняет
   отказ; сообщение получает статус «исправлено» или «отклонено» с пояснением.
2. **Given** элемент исправлен, **When** у него есть история выполнения, **Then** история
   не удаляется (конституция, принцип VII).

---

### Edge Cases

- Папка не найдена или пуста: агент сообщает об этом и ничего не сохраняет.
- Файл нечитаем (размытое фото, повреждённый PDF): в отчёте «не распознан» с причиной,
  остальная обработка продолжается.
- Формат файла не поддерживается (например, неизвестное расширение): в отчёте «пропущен»
  с причиной.
- Упражнение не подходит ни под один тип: сохраняется как «открытый ответ», в отчёте
  сообщение о новом типе.
- Номер урока не удаётся определить из имени папки: агент спрашивает номер.
- Урок с таким номером уже существует, но из другой папки: агент спрашивает, дополнить
  существующий урок или это ошибка.
- Слово в лексике с неоднозначным родом (`un/une élève`) или родом, меняющим смысл
  (`le/la livre`): сохраняются оба варианта / оба значения; при неуверенности — «требует
  проверки».
- Лист содержит только часть упражнения (продолжение на следующем фото): агент объединяет
  части в одно упражнение и указывает оба исходных файла.
- Одна и та же страница сфотографирована дважды (почти одинаковые фото): добавляется один раз,
  в отчёте — «дубль».
- Контент не проходит проверку формата: агент не сохраняет повреждённый элемент, исправляет
  его или сообщает об ошибке в отчёте.
- Обработка прервана на середине: уже сохранённое не должно оставаться в несогласованном
  состоянии — либо урок сохранён целиком, либо не сохранён.

## Requirements *(mandatory)*

### Functional Requirements

**Запуск и опись**

- **FR-001**: Навык ДОЛЖЕН вызываться командой агента с путём к папке урока и необязательными
  указаниями (темы, дата, выбор заданий и статусов).
- **FR-002**: Агент ДОЛЖЕН обрабатывать файлы папки урока (классная работа) и подпапки
  `Devoirs` (домашняя работа).
- **FR-003**: Перед сохранением агент ДОЛЖЕН показать опись: классификацию каждого файла,
  элементы, которые из него получатся, и для упражнений — предлагаемые номер, тему и краткое
  описание. Крупные сомнения — как понять файл (теория / справка / лексика / текст), как
  разрезать лист на элементы, какую тему назначить — агент ДОЛЖЕН выносить в опись вопросами
  и решать до обработки.
- **FR-004**: Пользователь ДОЛЖЕН иметь возможность указать, какие упражнения добавить
  и с каким статусом (основное / необязательное / резерв) и какие не добавлять вовсе.
  Если пользователь указал выбор, упражнения, не упомянутые в нём, ДОЛЖНЫ добавляться
  со статусом «резерв»; не добавляются только упражнения, которые пользователь явно
  исключил. Без выбора все упражнения добавляются как основные.
- **FR-005**: Номер урока ДОЛЖЕН определяться по имени папки `Leçon NN`; дату урока агент
  ДОЛЖЕН предлагать по датам файлов с подтверждением пользователя.

**Классификация и разбор**

- **FR-010**: Агент ДОЛЖЕН классифицировать каждый файл: теория, лексика, текст, лист
  упражнений, лист упражнений со справкой, медиафайл, дубль, не распознан.
- **FR-011**: Классификация теории и справки ДОЛЖНА следовать признакам: файл теории —
  объяснения занимают большую часть, файл в папке урока, название — тема; лист со справкой —
  основная часть пронумерованные задания, объяснение короткое (таблица сверху или сбоку).
- **FR-011a**: Изображения внутри теории ДОЛЖНЫ обрабатываться так: таблицы, примеры
  и другой передаваемый текстом материал — превращаться в форматированный текст; изображения,
  смысл которых текстом не передать (схемы, таблицы со специальными символами), —
  вставляться в теорию как изображения (сжатая копия фрагмента или файла); декоративные
  иллюстрации — отбрасываться без пометки.
- **FR-012**: Справка ДОЛЖНА прикрепляться к упражнениям своего листа; если она содержит тему,
  которой нет в теории урока, она ДОЛЖНА добавляться как элемент теории.
- **FR-013**: Один файл ДОЛЖЕН давать столько элементов, сколько в нём содержится (несколько
  упражнений, теория и упражнения, текст и упражнения к нему); упражнения к тексту ДОЛЖНЫ
  быть связаны с текстом.
- **FR-014**: Упражнение, продолжающееся на нескольких файлах, ДОЛЖНО сохраняться одним
  элементом со ссылками на все исходные файлы.
- **FR-015**: Каждое упражнение ДОЛЖНО получать тип из поддерживаемых (001, FR-020); если
  подходящего нет — «открытый ответ» с сообщением о новом типе в отчёте.
- **FR-016**: Формулировка задания ДОЛЖНА быть переведена на русский с сохранением оригинала;
  пункты упражнения ДОЛЖНЫ оставаться на французском, если задание не требует иного.
- **FR-017**: Для каждого упражнения, кроме «открытого ответа», агент ДОЛЖЕН указать все
  допустимые правильные ответы с происхождением «решено ИИ».
- **FR-018**: Пометки и ответы на фото ДОЛЖНЫ игнорироваться.
- **FR-019**: Для упражнений «по картинке» исходный файл ДОЛЖЕН прикрепляться для показа
  рядом с упражнением.

**Лексика и темы**

- **FR-020**: Лексика урока ДОЛЖНА извлекаться из файлов лексики: слово, перевод, словарная
  форма, род и артикль у существительных, тема. Файлы лексики бывают разными: список
  с переводом, список без перевода, картинки с подписанными словами.
- **FR-020a**: Если перевода в материале нет, агент ДОЛЖЕН перевести слово сам с пометкой
  происхождения «перевод ИИ»; то же для рода, артикля и словарной формы, если они не указаны
  в материале. Для слов с картинок, где подпись плохо читается или слово неоднозначно,
  ставится «требует проверки».
- **FR-021**: Слово, уже существующее в хранилище, НЕ ДОЛЖНО дублироваться — оно связывается
  с новым уроком. Слово определяется словарной формой, частью речи и родом (`le livre`
  и `la livre` — разные слова); при одинаковых форме, части речи и роде, но разном смысле
  (`la pêche` — персик / рыбалка) создаются разные записи. Если агент не может определить,
  то же это слово или другое, он ставит «требует проверки» с пояснением.
- **FR-021a**: У слова может быть несколько переводов; новые переводы из других уроков
  ДОЛЖНЫ добавляться к существующим, а не заменять их, с указанием урока, откуда перевод.
  Форма слова из материала (например, `belles` для `beau/belle`) сохраняется как пример.
- **FR-022**: Темы ДОЛЖНЫ выбираться из справочника тем; новая тема создаётся, только если
  подходящей нет, и указывается в отчёте. Темы, названные пользователем, имеют приоритет.
- **FR-023**: Каждому элементу ДОЛЖНА назначаться хотя бы одна тема; упражнения на повторение
  прошлых тем получают свои темы, а не тему урока.

**Качество, сохранение, отчёт**

- **FR-030**: Агент ДОЛЖЕН проверять результат: решения упражнений — повторной независимой
  проверкой; распознанный текст — сверкой с оригиналом. Элементы с сомнениями ДОЛЖНЫ получать
  пометку «требует проверки» с пояснением, что именно под сомнением; пояснение сохраняется
  в элементе и показывается в приложении (001, FR-041).
- **FR-030a**: Мелкие сомнения, возникшие во время обработки, — в распознанном слове,
  правильном ответе, типе упражнения, переводе слова — агент ДОЛЖЕН помечать «требует
  проверки» с пояснением, не прерывая обработку вопросами. Крупные сомнения решаются
  в описи (FR-003).
- **FR-031**: Каждый элемент ДОЛЖЕН получать происхождение и ссылку на исходный файл или
  ресурс (конституция, принцип I).
- **FR-032**: Перед сохранением контент ДОЛЖЕН проходить проверку формата (001, FR-005);
  элемент, не прошедший проверку, не сохраняется и указывается в отчёте.
- **FR-033**: Агент ДОЛЖЕН сохранять сжатые копии исходных изображений и документов
  в хранилище; аудио и видео ДОЛЖНЫ записываться как медиафайлы без копирования.
- **FR-034**: Сохранение урока ДОЛЖНО быть целостным: либо урок сохранён полностью, либо
  изменения не применены.
- **FR-035**: После сохранения агент ДОЛЖЕН автоматически, без отдельного подтверждения,
  зафиксировать изменения в приватном репозитории контента коммитом с понятным сообщением
  (например, «Урок 15: 6 упражнений, 23 слова») и отправить их в приватный удалённый
  репозиторий (резервная копия). Агент НЕ ДОЛЖЕН записывать контент в публичный репозиторий
  кода. Если отправка не удалась, агент сообщает об этом в отчёте; локальный коммит
  сохраняется.
- **FR-036**: Агент ДОЛЖЕН выдавать отчёт: итог по каждому файлу (добавлен как …, пропущен —
  причина, дубль, не распознан — причина), число элементов по разделам, элементы «требует
  проверки», созданные темы, новые типы упражнений.
- **FR-037**: Пользователь ДОЛЖЕН иметь возможность попросить переклассифицировать файл;
  агент заменяет только элементы этого файла.
- **FR-038**: Агент ДОЛЖЕН вести в хранилище контента читаемую человеком опись каждого урока:
  по каждому исходному файлу — часть урока, классификация, какие элементы из него получены,
  их темы, где лежит сжатая копия; для медиафайлов — расположение оригинала. Опись
  обновляется при каждом добавлении, дополнении и переклассификации.
- **FR-039**: Агент ДОЛЖЕН вести в хранилище общий указатель: список уроков с датами и темами
  и список тем со ссылками на уроки, где они встречаются. Опись и указатель — справочные
  документы для пользователя и разработки, в интерфейсе приложения не показываются.

**Повторный запуск, ссылки, исправления**

- **FR-040**: При повторном запуске для уже добавленного урока агент ДОЛЖЕН обрабатывать
  только новые файлы и продолжать сквозную нумерацию упражнений.
- **FR-040a**: Если уже обработанный файл изменился, агент ДОЛЖЕН показать это в описи
  с описанием изменений и предложить выбор: обновить элементы из этого файла (сохранив
  идентификаторы, статусы и историю выполнения там, где элементы соответствуют прежним),
  добавить как новые элементы или пропустить. Без решения пользователя изменённый файл
  не обрабатывается.
- **FR-041**: Навык ДОЛЖЕН поддерживать добавление материала по ссылке: элементы без урока,
  происхождение «внешний ресурс», ссылка, тема.
- **FR-042**: Навык ДОЛЖЕН поддерживать разбор сообщений об ошибках: исправление элемента
  или отказ с пояснением, закрытие сообщения; история выполнения при этом сохраняется.

**Экономия и границы**

- **FR-050**: Агент ДОЛЖЕН обрабатывать только то, что указал пользователь (конституция,
  принцип X); дорогие дополнительные операции (примеры к словам, объяснения) не выполняются
  без отдельного запроса.
- **FR-051**: Навык ДОЛЖЕН храниться в репозитории проекта вместе с описанием формата
  контента, на которое он опирается.

### Key Entities

- **Навык добавления урока**: инструкция агента — шаги обработки, правила классификации,
  формат результата, формат отчёта.
- **Опись**: предварительный список файлов с классификацией и будущими элементами; основа
  для выбора пользователя.
- **Отчёт об обработке**: итог по каждому файлу, счётчики элементов, элементы «требует
  проверки», новые темы и типы.
- **Опись урока (архив)**: читаемый человеком документ в хранилище — какие исходные файлы
  обработаны, как классифицированы, какие элементы и темы из них получены, где лежат копии.
  Служит справкой для пользователя и журналом для повторного запуска и переклассификации.
- **Общий указатель**: читаемый документ в хранилище — уроки с датами и темами, темы
  со ссылками на уроки.
- Элементы контента, темы, исходные файлы, медиафайлы, сообщения об ошибках — как в функции
  001.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Типичный урок (15–25 файлов) добавляется за одну сессию с агентом без ручной
  правки файлов контента.
- **SC-002**: 100% файлов папки урока упомянуты в отчёте и в описи урока с итогом.
- **SC-003**: 100% сохранённого контента проходит проверку формата приложения.
- **SC-004**: 100% ответов и переводов, созданных ИИ, имеют пометку происхождения.
- **SC-005**: На уроках-образцах 13 и 14 пользователь находит ошибки распознавания
  или ответов не более чем в 5% пунктов упражнений, не помеченных «требует проверки».
- **SC-006**: Повторный запуск для уже добавленного урока без новых файлов не меняет
  контент и не обрабатывает файлы заново.
- **SC-007**: Ни один файл контента не попадает в публичный репозиторий кода.
