# Research: Поиск (007)

Решение → почему → что ещё рассматривали.

## R1. Где живёт поисковый индекс

**Решение**: индекс строится в памяти при первом запросе для текущего `ContentIndex` и хранится
рядом с ним (`search_index(index)` кеширует по объекту индекса). `ContentStore` уже пересоздаёт
`ContentIndex`, когда файлы хранилища меняются, поэтому поиск сам видит новые слова и уроки
без перезапуска (FR-016).

**Почему**: контента мало (десятки уроков, тысячи слов — Assumptions), поиск перебором по
заранее разбитым на слова полям занимает миллисекунды. Отдельная база не нужна (XI).

**Отвергнуто**: SQLite FTS5 — нужен свой токенизатор для «начала слова», акцентов и «ё»,
плюс синхронизация с файлами контента; Whoosh / внешние поисковики — лишняя зависимость.

## R2. Нормализация (FR-004)

**Решение**: одна функция `normalize` для документа и запроса:
- `casefold`; `ё` → `е`; `œ` → `oe`, `æ` → `ae`;
- разложение NFKD и удаление диакритики (`é` → `e`, `ç` → `c`);
- слова — последовательности букв и цифр; апострофы (`'`, `’`, `ʼ`), дефисы и прочие знаки —
  разделители. `l'eau` → `l`, `eau`; `peut-être` → `peut`, `etre`.

Слова документа хранятся вместе с их положением в исходном тексте — для фрагмента с выделением
(FR-012). Та же нормализация повторена в `static/js/search.js` для подсветки на странице
теории; проверка — по quickstart.

## R3. Совпадение (FR-003, FR-005)

**Решение**: запрос `q1 … qn` совпадает в позиции `i`, если слова документа `d[i] … d[i+n-1]`
равны `q1 … q(n-1)`, а `d[i+n-1]` **начинается** с `qn`. Одно слово — только по началу
(`ange` не находит `manger`). Фраза `il y a` находит `il y avait`.

Запрос короче 2 символов (после нормализации, без пробелов) — пустой (Edge Cases).

## R4. Что ищется у каждого вида (FR-007)

- **Слово словаря**: французское с артиклем (`la maison`, `l'eau`) и каждый перевод.
  Скрытые (`hidden`) не ищутся. Если все слова запроса — артикли (`la`, `le`, `les`, `l`,
  `un`, `une`, `des`), слова словаря не ищутся (иначе нашлись бы все).
- **Теория**: название и текст. Текст — то, что видит пользователь: markdown рендерится
  тем же `render_markdown`, из HTML берётся текст (`html.parser`) — таблицы, списки,
  заголовки находятся, фрагмент без разметки.
- **Тема**: название.

Язык не выбирается: русские и французские слова лежат в одних полях (FR-006).

## R5. Порядок и группы (FR-008, Assumptions)

- Слова: совпадение во французском выше совпадения в переводе; затем по алфавиту.
- Теория: совпадение в названии выше совпадения только в тексте; затем урок (новые сверху).
- Темы: по названию.

В панели — первые 3 в группе и «Показать все (N)»; на странице результатов — все.

## R6. Фильтры и область (FR-009, US2)

- Область: `all` / `words` / `theory` / `topics`.
- Урок N: слова — у которых N в `lessons`, или урок N записан у перевода или примера
  (слова, добавленные из текста в 006); теория — урока N; темы — встречающиеся в уроке N
  (темы элементов урока и его слов).
- Тема T: слова и теория с темой T; группа тем — только сама T, если совпала.
- Состояние области и фильтров живёт только в полях формы поиска: при закрытии панели оно
  сбрасывается, на сервере и в браузере ничего не запоминается (FR-014).

## R7. Интерфейс: строка в шапке и панель (FR-001, FR-002, FR-008)

**Решение**: в `base.html` — форма `<form role="search" action="/search">` со строкой `q`,
скрытыми `scope`, `lesson`, `topic`. HTMX: `hx-get="/search/panel"` по событию
`input changed delay:150ms` и по смене области или фильтра, цель — панель под строкой.
Enter отправляет форму — открывается страница `/search` со всеми результатами. Alpine
открывает и закрывает панель (Esc, щелчок вне); при закрытии поля области и фильтров
сбрасываются. `autocomplete="off"` — браузер не копит историю запросов.

На узком экране строка занимает всю ширину шапки, панель — всю ширину экрана.

**Почему**: HTMX и Alpine уже в проекте; разметку результатов рисует сервер (один шаблон
на панель и страницу).

## R8. Переход и подсветка (FR-011, US3)

**Решение**: ссылка теории — `/elements/<id>?hl=<запрос>`. На странице элемента
`static/js/search.js` находит совпадения той же нормализацией (R2), оборачивает их
в `<mark class="search-hit">`, прокручивает к первому и показывает полоску: «← к результатам»
(`/search?q=…`), «Найдено на странице: N», «Следующее ↓», «Снять подсветку» (убирает
метки и `hl` из адреса). Метки заметок 005 (`mark.note-anchor`) не трогаются.

Слово ведёт на `/vocab/<id>`, тема — на `/topics/<id>` (у тем раздела «Лексика» страница
сама открывает вкладку «Слова»).

## R9. Перевод у найденных слов (FR-010)

**Решение**: настройка базы прогресса `search_translations` (`1` по умолчанию, `0` — скрыть),
флажок на странице «Настройки».

## R10. Производительность (SC-001)

Индекс: для каждого поля — список нормализованных слов с позициями. Запрос — проход по
полям с ранним выходом; на синтетических 5000 словах и 50 уроках теории — единицы
миллисекунд. Построение индекса (рендер теории) — один раз на версию контента.
Тест производительности — на синтетическом индексе с запасом по времени.
