# /add-lesson — добавить урок из папки материалов

Ввод пользователя: `$ARGUMENTS`

Перед началом прочитай `.claude/skills/_shared/content-rules.md` (правила разбора)
и `.claude/skills/_shared/report-template.md` (формат описи и отчёта). Формат файлов —
`docs/content-format.md`. Отвечай пользователю по-русски.

Все команды — `uv run french-learning …` из корня проекта. Хранилище — `CONTENT_DIR` из
`.env`, исходные материалы — `SOURCE_MATERIALS_DIR`. Операция `<op>` = `lesson-NNN`
(номер урока тремя цифрами).

## Какой это сценарий

- Путь к папке или «урок N» → **добавление / дополнение урока** (шаги 1–7).
  «Урок N» → папка `SOURCE_MATERIALS_DIR/Leçon NN`.
- «добавь домашку к уроку N» → то же, папка урока (новыми окажутся файлы `Devoirs`).
- «урок N: <файл> — это <классификация>» → **переклассификация** (раздел в конце).

## Шаг 1. Опись файлов

`scan-lesson "<папка>"`. Из результата:
- `lesson` — номер; `suggested_date` — предлагаемая дата;
- `conflict` — урок с этим номером уже добавлен из другой папки: **спроси**, дополнить его
  или это ошибка, и не продолжай до ответа;
- `existing: true` — урок уже есть: работай только с файлами `state: new`; `changed` покажи
  с описанием изменений и спроси решение (обновить / как новое / пропустить);
  `processed` **не читай**. Нет `new` и `changed` → сообщи «Новых файлов нет», ничего
  не меняй и закончи.
- `duplicate_of` — дубль (основным считается файл домашки).
- `kind: other` — неподдерживаемый формат → `skipped` с причиной.

Если черновик `.staging/lesson-NNN/` уже есть от прошлой незавершённой попытки — спроси,
продолжить его или начать заново (тогда удали папку черновика).

## Шаг 2. Просмотр

Прочитай каждый нужный файл **один раз** (изображения, PDF, docx). Для каждого определи
классификацию и какие элементы из него получатся (правила 1–3). Для упражнений —
тип, описание, тему, номер на листе. Запоминай всё нужное для шага 4 — повторно файлы
не читай.

## Шаг 3. Опись для пользователя → ждать ответа

По шаблону «Опись». Нумеруй упражнения так, как они будут пронумерованы во вкладке
(`next-number` даёт первый свободный номер). Включи: дату урока (подтвердить), темы,
вопросы по крупным сомнениям, для повторного запуска — блок изменений.
**Ничего не сохраняй до ответа пользователя.**

## Шаг 4. Обработка (по ответу пользователя)

1. `topics-list`; при необходимости — новые темы в `.staging/lesson-NNN/topics.yaml`
   (копия текущего `topics.yaml` + новые записи с id от `new-ids top`).
2. `new-ids` для всех новых элементов (и `les` для нового урока).
3. Для каждого исходного файла, из которого созданы элементы, — `store-source "<файл>"
   --lesson N --op lesson-NNN`; полученный путь — в `sources[].file` элементов
   и `stored_as` журнала. Медиа, дубли, нераспознанные — без копии.
4. Файлы элементов в `.staging/lesson-NNN/lessons/NNN/{theory,texts,exercises}/<id>.{md,yaml}`,
   лексика — `.staging/lesson-NNN/vocabulary/<id>.yaml` (для существующего слова — изменённая
   копия его файла с тем же id).
5. `lessons/NNN/lesson.yaml` в черновике (для существующего урока — копия с дополнениями):
   `date` (подтверждённая), `media` (аудио / видео), **журнал `files`** — по записи на **каждый**
   файл папки: `path` и `sha256` из `scan-lesson`, `part`, `classification`, `elements`,
   `stored_as`, `note` для duplicate / unrecognized / skipped.
6. Самопроверка (правило 8), затем `stage-check --op lesson-NNN`.

## Шаг 5. Сохранение

`commit-staging --op lesson-NNN -m "Урок N: X упражнений, Y слов, Z теории"`
(для дополнения: «Урок N: дополнение — …»). Команда сама обновит опись урока
(`inventory.md`) и указатель (`index.md`), сделает коммит и отправку.
`applied: false` → покажи нарушения, исправь черновик и повтори.

## Шаг 6. Отчёт

По шаблону «Отчёт»: итог по **каждому** файлу, счётчики, «требует проверки» с причинами,
новые темы и типы, пропущенное, результат коммита и отправки (`warning` — показать),
ссылка на урок в приложении.

## Переклассификация файла

«урок N: IMG_3765 — это теория»:
1. Найди файл в журнале `files` урока (`lessons/NNN/lesson.yaml`); его `elements` — что
   заменить.
2. Перечитай только этот файл; создай новые элементы по указанию (новые id).
3. В `.staging/reclass-NNN/_delete.txt` — пути файлов старых элементов (по одному в строке,
   относительно хранилища). Обнови запись журнала (`classification`, `elements`).
   Идентификаторы других элементов не меняются.
4. `commit-staging --op reclass-NNN -m "Урок N: <файл> — переклассификация"` и короткий отчёт.
